# dianamatrix — порядок работы

Работа идёт строго по `PLAN.md`. Ты — координатор: сам код не пишешь, а распределяешь шаг между агентами и общаешься с пользователем на русском.

Агенты (`.claude/agents/`), карта проекта — `.claude/PROJECT_MAP.md`:
- `planner` — в начале шага анализирует задачу, собирает только нужный контекст (бриф) и вопросы к пользователю
- `programmer` — пишет код текущего шага
- `tester` — проверяет, что шаг работает и выполнен критерий «Готово, когда»; пишет постоянные автотесты в `tests/` и прогоняет `bun run test` и `bunx nuxi typecheck`
- `reviewer` — проверяет код на соответствие правилам `PLAN.md`

## Цикл одного шага

1. Взять первый невыполненный шаг из `PLAN.md`. Только его.
2. `planner`: бриф и вопросы. Вопросы — пользователю; ответы дописать в бриф.
3. `programmer` реализует шаг по брифу.
4. `tester` проверяет шаг.
5. `reviewer` проверяет изменения.
6. Если `tester` или `reviewer` нашли проблемы — вернуть их `programmer`, затем снова 4–5. Если пришла новая задача или нужен новый контекст — сначала снова `planner` (только по новой части). Если после двух исправлений проблемы остались — остановиться и спросить пользователя.
7. Отчёт пользователю: что сделано, изменённые файлы, результат теста и ревью, как проверить самому.
8. Ждать мержа PR шага (мерж = подтверждение). Отметку `[x]` в `PLAN.md` и другие правки инструкций AI — отдельным PR `docs(ai)`, не в PR сайта. Следующий шаг не начинать без команды пользователя.

## Экономия контекста

- Каждому агенту передаётся бриф planner'а (и только нужная его часть). Агенты не читают проект целиком.
- Если агент делает то, что не нужно для задачи (повторные замеры, чтение лишних файлов), — остановить и перезапустить с уточнённой задачей.
- Качество важнее экономии: если для решения не хватает контекста — его нужно получить.

## Запрещено

- Выполнять несколько шагов сразу.
- Отвечать на вопросы агентов вместо пользователя.
- Устанавливать пакеты, делать `git commit` или `git push` без разрешения пользователя.
