# План разработки dianamatrix

Макеты: `docs/mockups/*.png`. Если чего-то нет в плане или в макетах — спросить, а не придумывать.

## Правила работы

1. Выполнять строго один шаг за раз, по порядку.
2. После каждого шага остановиться и написать: что сделано, какие файлы созданы/изменены, как проверить. Следующий шаг — только после подтверждения.
3. Ничего не решать самостоятельно и не угадывать. Любая неясность (размеры, тексты, поведение, названия) — вопрос пользователю.
4. Перед установкой любого пакета спросить: название, версия, зачем.
5. Пакетный менеджер — bun.
6. Не менять файлы, не относящиеся к текущему шагу.
7. `git commit` и `git push` — только по просьбе пользователя: push в `develop` сразу деплоит тестовый сайт lgaus.github.io/dianamatrix/dev/, push в `main` — основной lgaus.github.io/dianamatrix/. Порядок веток: feature → develop → main.
8. Общение с пользователем — на русском.
9. Мерж PR шага пользователем = подтверждение шага. Отметка `[x]` в этом файле и другие правки инструкций AI — отдельным PR `docs(ai)` после мержа.
10. Автотесты — Vitest + @nuxt/test-utils, лежат в `tests/` (тесты компонентов — `tests/components/`). Тестер пишет или дополняет тесты для нового кода. Пока идут правки по замечаниям — прогоняются только тесты изменённых файлов; все тесты (`bun run test`) и `bunx nuxi typecheck` — один раз после «го» пользователя (порядок — в `CLAUDE.md`). Тесты остаются в проекте. Автотесты не должны мешать менять тексты: формулировки в тестах не проверяются, только структура и данные.
11. Проверки вёрстки (шаги 5–12) тестер делает сам в браузере своего окружения, без пакетов в проекте: на ширинах 320 и 390 px (тач), планшет ~950 px (тач), 1024 и 1280 px (мышь) нет горизонтальной прокрутки, содержимое блоков не выходит за их границы (текст не обрезан и не вылезает), блоки не перекрываются; плюс стресс-проверка с удлинёнными текстами (примерно в 1,5 раза) на временной копии и с крупным шрифтом (корневой `font-size` 24px). Результат — скриншоты для пользователя. Постоянные Playwright-тесты в проекте — только если появятся проблемы (по решению пользователя).
12. Замечания по удобству (UX) агенты собирают и показывают пользователю как предложения; сами по ним ничего не правят.

## Правила кода

- Nuxt 4, Vue 3 `<script setup lang="ts">`, TypeScript, Tailwind. `ssr: false` в `nuxt.config.ts` не менять.
- Страница собирается из компонентов. `app/pages/index.vue` только компонует их, логики и разметки блоков в нём нет.
- Один компонент — один блок/элемент интерфейса.
- Значения нигде не хардкодятся в компонентах. Единственные источники:

| Что | Файл |
|---|---|
| Цвета, шрифты | `app/assets/css/theme.css` |
| Все тексты интерфейса | `app/content/texts.ts` |
| Расшифровки арканов | `app/content/arcana.ts` |
| Формулы расчёта | `app/utils/matrix/formulas.ts` |
| Типы данных матрицы | `app/utils/matrix/types.ts` |
| Чакры (id, цвет, какие точки); названия и зоны чакр — в `texts.ts` | `app/config/chakras.ts` |
| Дата рождения: маска, проверка, границы (`MIN_BIRTH_DATE`) | `app/utils/date/birthDate.ts` |

- `formulas.ts` и `birthDate.ts` — только чистые функции, без Vue и без импорта текстов/цветов.
- Комментарии в коде — на русском. Всё остальное в коде (имена переменных, функций, компонентов, файлов, шагов CI, названия тестов) — на английском.

## Дизайн-значения

Цвета (в скобках — токен в `theme.css`; стандартная палитра Tailwind отключена):
- акцент (фуксия) `#D1246B` (`accent`)
- наведение на элементы с фуксией — тёмная фуксия `#A11C52` (`accent-hover`)
- наведение/нажатие на кнопку с фоном акцента («Рассчитать», «Подтвердить») — фуксия с 40 % тёмной фуксии (`accent-shaded`, контраст белого текста ≈ 5,9 : 1)
- текст `#2A1520` (`ink`), вторичный текст `#6E5563` (`ink-muted`)
- рамки `#F7E1EA` (`line`), фон страницы `#FFF6FA` (`page`)
- рамки полей ввода `#F0CFDD` (`line-input`)
- фон карточек, узлы матрицы, активный таб `#FFFFFF` (`surface`)
- круг-заглушка фото `#F8D9E6` (`photo-placeholder`)
- сливочно-жёлтый `#F9E27D` (`cream`)
- линии матрицы `#C2387A` (`matrix-line`)
- цвет тени — `ink` с прозрачностью 12 % (`shadow`)
- аура за матрицей: `#FF8CC6` (`aura-1`), `#FFB3D9` (`aura-2`), `#E0B8FF` (`aura-3`) на `#FFEAF3` (`aura-base`) + зерно (opacity 0.1 — `opacity-grain`, soft-light — `--grain-blend-mode`)
- кольца узлов (чакры): фиолетовый `#8B3DFF` (`chakra-violet`), синий `#2E6BFF` (`chakra-blue`), голубой `#00B2E8` (`chakra-cyan`), зелёный `#12B76A` (`chakra-green`), жёлтый `#FFC400` (`chakra-yellow`), оранжевый `#FF8A00` (`chakra-orange`), красный `#FF3355` (`chakra-red`)

Шрифты:
- Comfortaa (`font-display`): все заголовки (700), логотип (700), крупные цифры «Предназначения» (400)
- letter-spacing −0.045em для всех заголовков (`tracking-heading`)
- Nunito 400–700 (`font-sans`, шрифт по умолчанию): текст и остальные цифры

Отклик на наведение (только при мыши, `hover:`) и нажатие (`active:`, тач): кнопки с фоном и строки меню — фон + полупрозрачная тёмная фуксия (`bg-accent-hover/tint`, прозрачность `--opacity-tint` 10 %), акцентный текст на нём — `accent-hover`; рамка кнопок с фоном (и бургера при открытом меню) затемняется — `border-accent-hover/tint-border` (прозрачность `--opacity-tint-border` 25 %); кнопки-текст — смена цвета. Плавно (150 мс) меняются только фон, цвет текста, рамка и масштаб; рамка фокуса появляется сразу. Наборы классов — `app/config/feedback.ts`.

Неактивные кнопки с фоном («Рассчитать», «Подтвердить»): `bg-line` + текст `ink-muted` с прозрачностью 60 % (`--opacity-disabled`), без отклика; класс `disabledFillClass` в `feedback.ts`. Неактивность — через `aria-disabled` (кнопка получает нажатия и показывает ошибку), не `disabled`.

Тени: выпадающее меню — `shadow-menu` (`0 8px 24px -4px`, цвет `shadow`).

Схема матрицы: линии ромба и квадрата — `matrix-line` с прозрачностью 70 % (`--opacity-matrix-edge`), оси и диагонали — 40 % (`--opacity-matrix-axis`); подпись под схемой — `ink-muted`, 13 px на телефоне (`text-caption-sm`) / 14 px (`text-sm`).

Карта здоровья: текст ячеек от `phablet` — 15 px (`text-cell`, в rem — растёт с крупным шрифтом). Предназначение: крупное число — Comfortaa 32 px (`text-number`, межстрочие 1), цвет `accent`. Перелом `lg` (64rem) объявлен в `theme.css` явно (`@theme static`), чтобы код мог читать `--breakpoint-lg`.

Переломы вне стандартных: `xs` 480 px (`--breakpoint-xs: 30rem`) — ниже него на `/about` короткий текст кнопки записи; `phablet` 550 px (`--breakpoint-phablet: 34.375rem`) — с него карта здоровья показывает зоны чакр.

Размеры вне шкалы Tailwind: скругления 28px (`rounded-block`, крупные блоки на компьютере), 20px (`rounded-card`, карточки) и 50 % (`rounded-t-arch`, верх арки логотипа; низ арки — `rounded-b-md`, 6 px); шрифты шапки 19px (`text-logo`) и 15px (`text-nav`); поля ввода и «Рассчитать» — скругление 14px (`rounded-field`), активный таб, кнопки и селекты календаря — 10px (`rounded-tab`); заголовок формы 38px (`text-title`) / 28px на телефоне (`text-title-sm`), межстрочие 1,15; текст полей 17px (`text-field`); наклейка формы на телефоне 13px (`text-badge-sm`).

- Тестовые правила:
  - `reduce(n)`: пока `n > 22` — заменить на сумму цифр.
  - A = reduce(день), B = reduce(месяц), C = reduce(сумма цифр года)
  - D = reduce(A+B+C), E (центр) = reduce(A+B+C+D)
  - углы: F = reduce(A+B), G = reduce(B+C), H = reduce(C+D), I = reduce(D+A)
  - A1 = reduce(A+E), A2 = reduce(A+A1), A3 = reduce(A1+E); то же для B
  - C1 = reduce(C+E), D1 = reduce(D+E)
  - Карта здоровья (Физика / Энергия, Эмоции = reduce(Физика+Энергия)): Сахасрара A/B, Аджна A2/B2, Вишудха A1/B1, Анахата A3/B3, Манипура E/E, Свадхистана C1/D1, Муладхара C/D. «Итого» = reduce(сумма столбца).
  - Предназначение: Небо = reduce(B+D), Земля = reduce(A+C), Личное = reduce(Небо+Земля); Мужское = reduce(F+H), Женское = reduce(G+I), Социальное = reduce(Мужское+Женское); Духовное = reduce(Личное+Социальное); Планетарное = reduce(Социальное+Духовное).
